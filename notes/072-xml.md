# 072: XML, the older cousin you will still meet
builds on: [062 CSV, rows and columns separated by commas](./062-csv-rows-and-columns-separated-by-commas.md), [066 JSON, records with names on every value](./066-json-records-with-names-on-every-value.md), [068 nesting, records and lists inside records](./068-nesting.md)
section: giving data a shape, part 12, ~2 min read

why does XML write every name twice? the same order that took one pair of curly braces in [JSON](./066-json-records-with-names-on-every-value.md), a format with name: value pairs, needs a pair of tags around every single value.

XML is a text format where each value sits between an opening tag and a closing tag with the same name, like `<customer>Asha</customer>`. tags nest inside each other, so it holds the same layered records as JSON ([nesting](./068-nesting.md), records inside records). here is order 103 from the shop (the imaginary gujarati snack store these notes run on), the one [068](./068-nesting.md) walked through, with khandvi, a steamed gram flour roll, and masala chai, spiced tea:

```text
<order>                          the order opens
  <order_id>103</order_id>       name, value, name again
  <customer>Asha</customer>
  <item>                         first item opens
    <product>khandvi</product>
    <quantity>1</quantity>
  </item>                        and closes
  <item>                         same tag again, thats the list
    <product>masala chai</product>
    <quantity>1</quantity>
  </item>
</order>
```

i went looking for the XML version of JSONs square brackets for lists, and there isnt one. a list is just the same tag showing up more than once. python reads it with ElementTree, a module that turns XML text into elements you search by tag, like json.loads gives a dictionary (same order on one line):

```python
import xml.etree.ElementTree as ET
text = "<order><order_id>103</order_id><customer>Asha</customer><item><product>khandvi</product><quantity>1</quantity></item><item><product>masala chai</product><quantity>1</quantity></item></order>"
order = ET.fromstring(text)  # xml text to an element, like json.loads
print(order.find("customer").text)
items = order.findall("item")  # every child tagged item, in order
print(len(items), "items")
for item in items:
    print(item.find("product").text, repr(item.find("quantity").text))
print(len(text))
```

```output
Asha
2 items
khandvi '1'
masala chai '1'
190
```

the quantity comes back as the text '1', not a number, same as splitting a [csv](./062-csv-rows-and-columns-separated-by-commas.md), a text file of comma split rows. XML itself has no number type, so your code decides what each value is. and repeated names cost bytes: 190 characters here, against 130 for the same order as one line of JSON with python default spacing.

you still meet it: sitemaps, the files telling search engines which pages a site has, are XML.
